# ローカルLLM（Ollama）とAPIの仕組みまとめ

## 概要

本プロジェクトでは、Ollama を利用し、
ローカル環境で動作するチャットアプリを構築しています。

一見すると「API通信」を行っているように見えますが、
実際には **完全にローカル環境内で処理されています。**

---

## ローカル動作の仕組み

以下のコードがポイントです：

```python
"http://localhost:11434/api/chat"
```

### localhostとは

* `localhost` = 自分自身のPC
* 外部サーバーではなく、**ローカル環境を指す特別なアドレス**

---

## データの流れ

```text
Pythonプログラム
    ↓
localhost（自分のPC）
    ↓
Ollama（ローカルAIサーバー）
    ↓
ローカルに保存されたLLMモデル（例：gemma3:1b）
```

👉 **すべてPC内部で完結している**

---

## APIの正体

「API」と聞くと外部通信のイメージがありますが、
ここでは少し意味が異なります。

### APIとは

👉 プログラム同士のやり取りのルール

Ollamaは内部でローカルサーバーを起動しており、
そこにHTTPでアクセスしているだけです。

---

## `/generate` と `/chat` の違い

### `/api/generate`

* 単発のテキスト生成
* 会話の文脈を持たない

```json
{
  "model": "gemma3:1b",
  "prompt": "こんにちは"
}
```

---

### `/api/chat`（推奨）

* 会話形式
* 履歴を持てる

```json
{
  "model": "gemma3:1b",
  "messages": [
    {"role": "user", "content": "こんにちは"}
  ]
}
```

👉 チャットアプリを作るならこちらを使う

---

## 会話履歴の重要性

チャットの自然さは以下で決まります：

* 過去の発言を送っているか
* systemプロンプトの有無

### 例

```python
messages = [
    {
        "role": "system",
        "content": "自然で落ち着いた会話をするアシスタント"
    }
]
```

👉 会話の「性格」を決めることができる

---


## まとめ

* `localhost` を使っているため完全ローカル動作
* APIは外部通信ではなく「内部通信」
* `/chat` を使うことで自然な会話が可能

👉 シンプルな構成でも「自作AI」は実現できる
